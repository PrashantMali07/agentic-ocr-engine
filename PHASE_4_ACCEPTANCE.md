# Phase 4 acceptance record

19 October 2026. Local code and fixture validation only; no deployment or external monitoring was configured. The code and local integration checks are complete; production acceptance still requires the independent accuracy and operational checks below.

## Completed checks

- The 51 security tests pass, including durable review/version conflicts, retention, readiness and alerts, worker resource observations, graph checkpoint cleanup, and the accuracy evaluator's table-text normalization.
- `scripts/measure_phase04_load.py` admitted three distinct scanned PDFs from `test_asset` concurrently to the same SQLite queue. Two separate worker OS processes shared that queue on an AMD Ryzen 7 5700X host with 30 GiB RAM. All three jobs completed, each in one attempt; at most one OCR child was observed processing at a time. No alert labels remained active at the end. Temporary job data was removed after the run.
- The process-level CPU run took 124.88 seconds for three jobs (1.441 jobs/minute). The longest observed queue wait was 85.82 seconds, longest end-to-end latency 123.33 seconds, and longest OCR attempt 47.42 seconds. Sampled peak OCR-child RSS was 5,434,712,064 bytes (5.06 GiB); sampled peak local job artifacts were 748,062 bytes. These are maxima among the three jobs, not whole-host high-water marks. This small sample does not establish p95/p99 latency or worst-case capacity.
- `scripts/evaluate_phase04_acceptance.py` now scores visible text in PP-StructureV3 HTML tables rather than HTML tags, and a regression assertion covers this. The evaluator still requires independently verified full transcripts and field values before it will run real-scan CER/WER checks.
- `scripts/validate_phase04_fastapi_gpu.py` started `uv run --no-sync ingest-api` and two worker processes with a temporary credential and SQLite directory. It submitted three scanned PDFs concurrently through `POST /extract/v1` and polled `GET /extract/v1/{job_id}` on an NVIDIA GeForce RTX 2060. All three completed with nonempty results and one attempt each. The run took 73.40 seconds; maximum observed queue wait was 50.29 seconds and maximum end-to-end latency was 72.35 seconds. Sampled peak OCR-child RSS was 2,847,559,680 bytes (2.65 GiB), per-process GPU memory 2,805,989,376 bytes (2.61 GiB), and local job artifacts 748,062 bytes. There were no retries, active alerts, or readiness failures at completion. The validator waits for all worker observations after the HTTP results become terminal, avoiding a reporting race.
- Local `.env` sets `ENCRYPTED_BACKUPS=false`; `config.py` accepts only `true` or `false`. Production should set `true` after an encrypted backup process is configured. The flag does not create or encrypt backups.

## Acceptance gates still open

1. An independent reviewer must verify full transcripts and field-to-label/table-row associations for a representative scanned corpus, including the five `RFQ_06`–`RFQ_10_scanned.pdf` fixtures. The business owner must set maximum CER/WER and minimum field/association accuracy thresholds before scoring. The 46-value Phase 3 spot check is not independent ground truth. Value presence alone does not prove association.
2. The operator must connect `/ready` and admin `/operations/metrics` to an external monitor and alert destination, then verify alert delivery. No external destination was supplied or changed here.
3. The operator must choose and implement encrypted SQLite backup storage, key management, access control, retention, and a restore drill. The live database TTL does not expire copies in backups. `ENCRYPTED_BACKUPS=true` is a policy setting only; no backup destination or encryption key was supplied or changed here.
4. Larger, representative concurrency and soak runs on the deployment target are still needed for throughput, p95/p99, RAM/VRAM, scratch-disk, timeout, retry, and failure budgets. The three-scan CPU and FastAPI GPU runs check queue serialization and a bounded local workload only.

To repeat the local CPU check, run `PYTHONPATH=src .venv/bin/python scripts/measure_phase04_load.py --device cpu --workers 2`. To repeat the FastAPI GPU check on a host with a working NVIDIA driver, run `.venv/bin/python scripts/validate_phase04_fastapi_gpu.py` while port 8000 is free. The supplied scans remain in `test_asset`; test jobs and credentials are temporary. For transcript scoring, see the input format in `scripts/evaluate_phase04_acceptance.py`; keep verified labels outside version control if they contain private document data.

A blank, owner-only label template has been prepared at `phase04_review/ground_truth_template.json`. See [the independent-review runbook](docs/runbooks/phase04-independent-review.md) for the reviewer procedure. The template is incomplete by design and has not been counted as acceptance evidence.
