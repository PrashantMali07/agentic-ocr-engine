# Independent scan accuracy review

Run `python scripts/prepare_phase04_review.py` once from the repository root. It creates an ignored, owner-only `phase04_review/ground_truth_template.json` containing blank labels and SHA-256 digests for the five scanned RFQ PDFs in `test_asset`. It never copies OCR output or the assistant's earlier value guesses into the template. The generator refuses to overwrite a review directory.

To accelerate transcription, a VLM may first draft text and table cells from page images. Keep its drafts separate from the verified template and have the reviewer correct them against the source PDFs without looking at the OCR result. See [the VLM test-suite plan](../../VLM_TEST_SUITE.MD). The VLM itself is not the independent reviewer.

An independent reviewer should inspect each source PDF directly and fill `verified_by`, `verified_at`, a complete visible-text transcript in reading order, every expected field value, and its `field_locations` entry (page, label, optional table row/column, and an excerpt from the reviewed transcript). Add or remove field keys and their matching locations together to match the document; the supplied keys are a checklist only. Include text inside table cells in the transcript. Keep the JSON private because it contains document data. The evaluator rejects empty labels, missing source digests, and scans whose bytes no longer match the template; the association gate also requires complete locations.

Separately compare each field's label, table row and column, and value in the OCR result against the source PDF. Run the accuracy evaluator with `--private-extracted-output phase06_evidence/extracted.json`, then use `scripts/prepare_phase04_associations.py template` to create one checklist item per field. Record any mismatched association, even when the value appears elsewhere in the OCR text, and finalize the completed checklist with the same script. The current API produces document text and table HTML, not normalized business-field objects, so `field_value_presence` is only a coverage metric. Do not treat it as structured-field accuracy or use it alone for automatic decisions.

Before scoring, the business owner must set maximum CER and WER, minimum value presence, and an acceptable association-error rate. Run `PYTHONPATH=src .venv/bin/python scripts/evaluate_phase04_acceptance.py --ground-truth phase04_review/ground_truth_template.json --device cpu --max-cer NUMBER --max-wer NUMBER --min-field-value-presence NUMBER` after the reviewer finishes the file. Repeat with `--device gpu` only when a working GPU is available. The command prints scores and missing field names, not transcript text. Preserve the score and the independent association review as private acceptance evidence.

Example: a scanned RFQ has a table with row A, quantity 10, price 125; and row B, quantity 20, price 180. OCR returns both prices correctly as text but swaps their rows, so a search for `125` and `180` reports 100% value presence. The business answer is still wrong: both price-to-row associations fail. The reviewer records the full visible transcript and the four expected quantity/price associations directly from the source PDF, then marks the swapped prices incorrect in a separate association review. CER (character error rate) and WER (word error rate) measure transcript mistakes; value presence measures whether expected values appear anywhere; association accuracy measures whether each value is attached to the correct label, row, and column. The business owner might **hypothetically** require CER at most 3%, WER at most 8%, value presence at least 98%, and association accuracy at least 99% before automation. Those numbers are an illustration, not approved thresholds for this project.
