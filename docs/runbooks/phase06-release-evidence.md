# Phase 6 release evidence

These checks concern the active single-host FastAPI/SQLite legacy OCR path. They do not enable LangGraph, Temporal, callbacks, or deployment. Create `phase06_evidence/` with owner-only permissions (for example, `install -d -m 700 phase06_evidence` on Linux); the directory is ignored by Git.

1. An independent reviewer completes private scanned-PDF ground truth described in [the Phase 4 runbook](phase04-independent-review.md), including `field_locations` for every scored field. `scripts/prepare_vlm_review.py` can draft transcripts from page images with a locally selected VLM runner, but its output is not verified ground truth. A separate itemized review compares every source label/page/row/column/value to the OCR output. `scripts/prepare_phase04_associations.py` makes the checklist and recomputes counts; the reviewer must inspect both the source scans and OCR output.
2. The business owner copies [the policy example](phase06-quality-policy.example.json), replaces every `null` with an approved number, and signs the `verified_by`/`verified_at` fields **before** the staged measurement. Ratios are between 0 and 1, times are seconds, memory/artifact limits are bytes, and throughput is jobs per minute. The gate requires at least 100 GPU jobs for a meaningful p99 sample.
3. On a machine with a functioning GPU driver and the production-selected model bundle, collect scan accuracy with `PYTHONPATH=src .venv/bin/python scripts/evaluate_phase04_acceptance.py --ground-truth phase06_evidence/ground_truth.json --device gpu --private-extracted-output phase06_evidence/extracted.json > phase06_evidence/accuracy.json`. Generate `association_template.json` with `scripts/prepare_phase04_associations.py template --ground-truth phase06_evidence/ground_truth.json --extracted phase06_evidence/extracted.json --output phase06_evidence/association_template.json`. After an independent reviewer fills every item, run its `finalize` command with `--review phase06_evidence/association_reviewed.json --output phase06_evidence/associations.json` and the same ground-truth/extracted paths.
4. Prepare a private workload manifest using [the example](representative-gpu-workload.example.json), enlarged to the approved representative soak. Run `PYTHONPATH=src .venv/bin/python scripts/measure_representative_gpu.py --manifest phase06_evidence/workload.json --output phase06_evidence/gpu_load.json --jobs-output phase06_evidence/gpu_jobs.json`. This uses the actual `ingest-api` FastAPI route, two local worker processes, multiple test tenants, and temporary SQLite. `scripts/validate_phase04_fastapi_gpu.py --rounds 34` remains a repeated-scan regression, not the release-capacity evidence.
5. Run `PYTHONPATH=src .venv/bin/python scripts/check_phase06_quality.py --policy phase06_evidence/policy.json --ground-truth phase06_evidence/ground_truth.json --accuracy phase06_evidence/accuracy.json --extracted phase06_evidence/extracted.json --associations phase06_evidence/associations.json --workload-manifest phase06_evidence/workload.json --gpu-load phase06_evidence/gpu_load.json --gpu-jobs phase06_evidence/gpu_jobs.json`. A nonzero exit means the quality/capacity evidence is incomplete or outside the owner-approved thresholds. The script checks exact ground-truth/OCR/workload bindings, every association verdict, every admitted GPU job, corpus size, reviewer metadata, latency, throughput, retries, and sampled resource peaks. Manual review and host-level traces still need independent audit.

The remaining release gates are separate: GPU image build and offline container smoke, image/dependency vulnerability scan and SBOM, approved model publisher provenance, encrypted backup plus restore drill, external alert delivery, ingress/auth/TLS verification, and a representative target-host soak. The `ENCRYPTED_BACKUPS` flag is only a deployment assertion, not a backup implementation. Do not mark release ready from this quality script alone.
