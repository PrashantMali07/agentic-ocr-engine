# Phase 3 code implementation — bounded extraction

18 October 2026. No deployment was performed.

The active single-host `legacy` worker now preflights supported inputs before parsing. Limits cover PDF pages and page dimensions, image pixels and frames, DOCX/XLSX archive members and expansion, text bytes, spreadsheet and CSV dimensions, native document blocks, and serialized output. Password-protected, corrupt, unsupported, and wholly empty inputs fail explicitly with safe error codes. These checks complement the worker deadline; they do not impose a process memory limit.

PDF extraction now selects digital pages without OCR in the native parser and sends every scanned page through OCR one page at a time, in original page order. The worker checks that each OCR call returns exactly one result. It records attempted and empty page numbers. When a PDF has content on some pages and none on others, the document and job finish as `partial`, preserving the result for the caller. Image OCR validates dimensions before loading or upscaling. Tesseract has a deadline. Ambiguous OCR corrections are suggestions; recognized content is not silently rewritten, and absent confidence remains unknown.

The native DOCX/HTML, XLS/XLSX, and CSV parsers now have explicit iteration and output bounds. The checked-in OpenAPI documents the new partial status and result fields. Validation found that a broad Paddle table box could suppress text Tesseract recognized but the table HTML omitted. Reconciliation now checks token coverage before discarding overlapping lines and records recovered blocks as Tesseract-sourced. Tests cover that case, page order and partial reporting for mixed PDFs, input and archive limits, encrypted/corrupt files, spreadsheet/CSV bounds, correction provenance, safe failure, and partial job persistence. Real scanned PDFs completed through the worker subprocess; after fixing explicit device selection, five scanned fixtures completed on verified CPU and GPU through the extraction manager. See [PHASE_3_VALIDATION.md](PHASE_3_VALIDATION.md) for fixture and quality results.

Remaining acceptance gate: the supplied real scans have no independently verified transcripts, so WER/CER cannot be scored. A manual value-presence check found 46/46 transcribed strings on both explicitly selected CPU and GPU, but this does not replace a labeled real-scan corpus or test structured field accuracy. The inactive graph/Temporal/decoupled paths still need consolidation around the bounded format dispatcher and rendering contract before they can be enabled. Process memory/disk limits and load measurements also remain open. Phase 4 covers durable human review, result retention/expiry, and operational metrics; later phases cover callback delivery and distributed topology if required.
