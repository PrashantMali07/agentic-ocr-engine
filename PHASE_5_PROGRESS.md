# Phase 5 code progress

19 October 2026. No deployment was performed.

The reviewed `urllib3` advisories affected the lock's former 2.7.0 version. The upstream project lists 2.8.0 as the patched release for [HTTPS proxy TLS configuration](https://github.com/urllib3/urllib3/security/advisories/GHSA-8988-9cw3-xx77), [chunked Deflate streaming](https://github.com/urllib3/urllib3/security/advisories/GHSA-gh4c-6fx4-qh6g), and [unbounded chunk-size lines](https://github.com/urllib3/urllib3/security/advisories/GHSA-vxq7-64xx-v4gw). `pyproject.toml` and `requirements-cpu.txt` now require `urllib3>=2.8.0,<3`, and `uv.lock` resolves 2.8.0. `uv lock --check --offline` passed; the local virtual environment was upgraded to 2.8.0 and the full 52-test suite passed after the model-integrity test was added. This addresses those specific advisories in the dependency definitions; it is not a complete dependency or container vulnerability scan. Runtime reachability through transitive model-download clients has not been established.

`scripts/prefetch_models.py` now selects CPU and matches the active legacy PP-StructureV3 model configuration, including the table, layout, and unwarping options. It initialized successfully from the local cached models.

Both Dockerfiles now reference immutable digests for their Python, CUDA, and uv images. `requirements-cpu.lock` resolves the CPU runtime to exact versions and package hashes for Linux x86-64/Python 3.11; `Dockerfile.gpu` continues to install the GPU runtime from `uv.lock` and now uses the CPU lock for its disposable build-time model download environment. The CPU lock includes the missing `python-dotenv` and `pymupdf4llm` imports found by a container smoke test. The CPU image was built locally and passed an API startup, `/health`, and PP-StructureV3 constructor smoke test with container networking disabled. Its standalone output path is writable without Compose.

`model-artifacts.json` pins SHA-256 hashes for the 12 PP-StructureV3 model directories observed in the active legacy path. Both image builds download the models before runtime and compare every model file against this checked-in manifest. The application passes those local directories explicitly to PaddleOCR, and the API and worker verify the manifest at startup. An additional unit test rejects changed, missing, and symlinked model files. The CPU build fetched a clean copy from the official model host and matched the manifest. The manifest was initially recorded from this workstation's model cache, so its hashes demonstrate consistency, not independent publisher provenance; model source revisions and provenance still need review before release.

The GPU image reached dependency installation and verified the clean 12-model download against the manifest. Its first export lost the Docker connection; the retry was stopped at the user's request during final export. No GPU image or container smoke result is claimed. The earlier Phase 4 GPU validation through the local FastAPI backend remains valid, but it did not test this Docker image. No further image builds are planned without a new request.

OS packages installed with `apt-get` are still selected by current distro repositories, so the image build is not fully reproducible despite the base-image and Python pins. An image vulnerability scan and a representative release-host soak test remain open. Optional callbacks remain disabled; enabling them would require tenant-owned destinations, egress/DNS/redirect protections, signatures, delivery persistence, and bounded retries. The dormant Temporal client, workflow, and activity now reject callback URLs before any delivery; the optional LayoutReader requires a local-only model directory. The Dockerfile model directories are made read-only in source, but those edits have not been built or container-tested.

Phase 6 code-level checks and the remaining release gates are tracked in [Phase 6 code progress](PHASE_6_CODE_PROGRESS.md). The earlier 52-test count is a historical result; the current full suite result is recorded there.
